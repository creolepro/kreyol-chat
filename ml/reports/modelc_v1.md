## Gate 6 — first-position logit margin (closing the v0 flat-distribution story)

v0 *asserted* that native(HF)↔llama.cpp greedy divergence on open-ended base-LM prompts was numeric instability on a flat next-token distribution. v1 tests it directly: for the first generated position of each of the 10 frozen prompts, the native fp32 top-1 margin is compared to the fp32↔f16 delta (the exact perturbation llama.cpp's f16 weights introduce), with HF's own f16 argmax flip as the in-framework control.

> **Finding — the v0 flat-distribution explanation is REFUTED. First-position top-1 margins average 0.6866 vs a fp32↔f16 delta of 0.0125 (~55×) and HF f16 NEVER flips (0/10) — the argmax is numerically STABLE. Yet native↔llama.cpp greedy still diverges, so the cause is NOT dtype noise and NOT the weights (gate1 export Δ=0, gate4 token-ID parity 1.0, gate5 ONNX greedy matches native): it is a generation-path difference (BOS / prompt-boundary handling in llama-completion).**

Mean first-position top-1 logit margin **0.6866** vs mean fp32↔f16 delta **0.0125** (~**55×**); margins at/below the delta on **0/10** prompts; HF-f16 argmax flips on **0/10**; native↔llama.cpp greedy LCP mean **0.002**.

So the first-token argmax is **numerically robust** — f16 rounding is ~two orders of magnitude too small to move it, and it never does. The divergence is therefore **not** dtype noise (which refutes the v0 hand-wave) and **not** the weights: gate 1 export Δ=0, gate 4 token-ID parity 1.000, gate 5 ONNX greedy matches native. It is a **generation-path** difference.

**Root cause (probed, CPU).** The native HF path always prepends `<|bos|>` (id 24567); llama.cpp's default generation path does not prepend a BOS at all by default — its llama-tokenize ids are `[7739, 33, 7492, 312]` by default vs `[7739, 33, 7492, 312]` with `--no-bos` (identical). The GGUF *records* `bos_token_id=24567` but sets no add-BOS default, so the two runtimes start from a different first-position context. That prompt-boundary mismatch — not any conversion defect — is what separates the greedy paths; a post-SFT chat model with a fixed template + sampling is unaffected.
